# Deploying this ACF installation

Generated by `acf-setup init`. ACF v1.0 is read-only: every mutation is refused.

- Gateway: `{gateway_host}`.
- Control plane: `{control_plane_host}`.
- Agent devices: {devices}.
- Environment and secret namespace: `{env}`.

## What is here

| Directory | Install on | Location |
| --- | --- | --- |
| `gateway/` | The gateway host | `{etc}/gateway` |
| `control-plane/` | The control-plane host | `{etc}/control-plane` |
| `agent-<device>/` | That agent host | `{etc}/agent` |
| `offline/` | **No server.** An offline machine or encrypted storage | — |

`offline/` holds the CA key and the administrator keys that sign configuration and job definitions. Anyone who holds them can admit configuration, so they must never be copied to a server.

## 1. Accounts and directories (each host, as root)

```bash
# gateway host
useradd --system --home-dir {state}/gateway acf-gateway
install -d -o acf-gateway -g acf-gateway -m 0700 {state}/gateway
cp -r gateway {etc}/gateway
chown -R root:acf-gateway {etc}/gateway && chmod -R g-w,o-rwx {etc}/gateway
chown acf-gateway {etc}/gateway/tls/*.key {etc}/gateway/keys/*

# control-plane host
useradd --system --home-dir {state}/control-plane acf-control-plane
install -d -o acf-control-plane -g acf-control-plane -m 0700 {state}/control-plane
cp -r control-plane {etc}/control-plane
chown -R root:acf-control-plane {etc}/control-plane && chmod -R g-w,o-rwx {etc}/control-plane
chown acf-control-plane {etc}/control-plane/tls/server.key {etc}/control-plane/keys/authority.key

# each agent host
groupadd --system acf-agents
useradd --system --gid acf-agents acf-daemon
cp -r agent-<device> {etc}/agent
chown -R root:acf-agents {etc}/agent && chmod -R g-w,o-rwx {etc}/agent
chown acf-daemon {etc}/agent/tls/client.key
usermod -aG acf-agents <agent-user>   # and pass its UID with --agent-uid, or edit the unit
```

## 2. Create the secret store (gateway host)

```bash
sudo -u acf-gateway acf-store --config {etc}/gateway/config/bundle.yaml \
  --profiles {etc}/gateway/config/profiles init --namespace {env}
```

## 3. Start the services

```bash
cp control-plane/acf-control-plane.service gateway/acf-gateway.service /etc/systemd/system/   # per host
cp agent-<device>/acf-agent.service /etc/systemd/system/                                     # agent hosts
systemctl daemon-reload
systemctl enable --now acf-control-plane   # first: the gateway checkpoints its audit log here
systemctl enable --now acf-gateway
systemctl enable --now acf-agent
```

The gateway refuses new requests if no audit checkpoint is accepted for 5 minutes, so keep the control plane running.

## 4. Add a read-only connector (on the machine holding this directory)

1. Put a connector profile (`acf.profile/v1`) in `gateway/config/profiles/`. Add its resource and secret registration to `gateway/config/bundle.yaml`, and an `allow` rule to `gateway/config/policy.yaml`.
2. Entitle each device in `control-plane/config/authority.yaml`. Then add a job definition (`acf.job/v1`) to `control-plane/config/jobs/` naming the devices that may run it.
3. Run `acf-setup admit --out <this directory>`. It checks the production rules and re-signs everything.
4. Copy `gateway/config` and `control-plane/config` to the hosts, then restart both services.
5. Load the credential. The value is read from standard input, never from an argument:

   ```bash
   sudo -u acf-gateway acf-store --config {etc}/gateway/config/bundle.yaml \
     --profiles {etc}/gateway/config/profiles put secret://{env}/<path> < token-file
   ```

An agent then opens a task and acts through the daemon:

```bash
acf-agent task create --socket /run/acf-agent/acf.sock --task t1 --job <job-id>
acf-agent action execute --socket /run/acf-agent/acf.sock --task-handle <handle> \
  --action <action> --resource <resource>
```

For an MCP client such as Claude Code, run the read-only adapter as the agent's user:

```bash
claude mcp add acf -- acf-agent mcp --socket /run/acf-agent/acf.sock
```

## 5. Check the audit trail

On a machine that can read both the gateway's `{state}/gateway/audit.jsonl` and the control plane's `{state}/control-plane/checkpoints`:

```bash
acf-control-plane verify-audit --log audit.jsonl --checkpoints checkpoints \
  --audit-keys {etc}/control-plane/config/audit-keys.yaml
```

## Limitations (v1.0)

- **Read-only:** mutations are refused.
- **Store:** integrity only, with no rollback resistance. An older copy of the store can bring back an older credential.
- **Certificates:** expire after the days chosen at `init` (default 90). Reissue them from `offline/ca.key` before then.
- **Revocation, enrollment, and job definitions:** edited as files; there is no administrative API.
